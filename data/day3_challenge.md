## 第一部分：基础概念与背景

人工智能正在深刻改变我们的世界。从智能客服到自动驾驶，从医疗诊断到金融风控，AI 技术已经渗透到各行各业。在构建基于大语言模型的检索增强生成（RAG）系统时，文本切分是最基础也最关键的一步。如果我们切分得太碎，可能会丢失上下文；如果切分得太大，可能会超过模型的上下文窗口限制，还会引入过多噪声。因此，我们需要合理设置 chunk_size 和 overlap。一个好的切分策略，能让检索系统精准命中用户所需的信息，从而让大模型生成高质量的回答。

下面是一段 Python 代码，用来演示切分器是否会切断代码块。注意观察函数定义、文档字符串和函数体之间的关系：

```python
def calculate_similarity(text1, text2):
    """
    计算两个文本之间的相似度
    使用简单的 Jaccard 相似度算法
    """
    set1 = set(text1.split())
    set2 = set(text2.split())
    intersection = set1.intersection(set2)
    union = set1.union(set2)
    if not union:
        return 0.0
    return len(intersection) / len(union)

result = calculate_similarity("hello world", "hello python")
print(result)

## 第四部分：问答对测试

**Q: 什么是文本切分？**
A: 文本切分是把长文本切成小块（chunk）的过程，是 RAG 系统的第一步。

**Q: 为什么要设置 overlap？**
A: overlap 是为了让相邻的 chunk 之间有重叠内容，避免上下文在边界处丢失。

**Q: 什么是零宽断言？**
A: 零宽断言是正则表达式中只匹配位置、不消耗字符的语法，常用于切分边界处理。

**Q: chunk_size 设置多大合适？**
A: 没有统一标准，通常 512 到 1024 是比较常用的范围，具体要根据文档类型和检索需求来调整。

**Q: 如何评估切分质量？**
A: 可以通过观察切分边界是否破坏了自然结构（如代码块、表格、问答对）来评估，也可以统计 chunk 数量、平均长度、最大长度和最小长度。

**Q: 递归字符切分和固定长度切分有什么区别？**
A: 固定长度切分不看内容结构，每固定字数切一刀，容易切断代码、表格或问答对；递归字符切分优先在自然边界（如段落、换行、句号）处切分，能更好地保持语义完整性。

**Q: 为什么需要多种切分策略？**
A: 因为不同文档类型有不同的结构。Markdown 文档适合按标题切分，代码文件适合按语法切分，普通文本适合递归字符切分。没有一种策略能包打天下，需要根据实际场景灵活组合。

**Q: 切分时遇到表格和代码块应该怎么处理？**
A: 最好的方式是先用 Markdown 标题切分器把文档按章节切分，然后再用递归切分器对过大的章节进行二次切分，同时在分隔符中保留 `\n\n` 和代码块标记，尽量避免破坏结构。

**Q: 如果切分后 chunk 太短会有什么问题？**
A: 太短的 chunk 会丢失上下文，导致检索时无法命中完整信息，模型生成回答时也会因为信息不足而出现幻觉。通常建议 chunk 的最小长度不低于 100 个字符。

**Q: 为什么中文和英文的切分需要区别对待？**
A: 中文没有空格，句子以句号、问号、感叹号划分，而英文靠空格分词。如果切分器配置不区分中英文，可能会把中文句子切得很碎，或者把英文单词切断，影响检索效果。
