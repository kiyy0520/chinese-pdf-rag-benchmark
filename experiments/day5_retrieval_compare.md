# Day 5：BM25 + RRF 混合检索实验报告

## 一、实验背景
为了验证混合检索是否能有效提升检索质量，我们在 `recursive_512_0` 切分配置下，对 20 条 Golden QA 进行了评估。

## 二、RRF 参数记录
- **RRF k 值**：60
- **权重**：(1.0, 1.0) 即 BM25 和向量各占一半
- **融合前候选数**：20

## 三、三种检索方案对比表

| 方案 | Recall@5 | MRR | 备注 |
| :--- | :--- | :--- | :--- |
| 纯向量 | 0.8000 | 0.8000 | 语义理解强，但对排版/公式匹配弱 |
| 纯 BM25 | 0.8500 | 0.8500 | 专业术语命中率极高，当前语料的最优单路方案 |
| 混合检索（k=10, 权重1.0:0.5） | 0.8500 | 0.8250 | 经过参数调优，MRR较默认参数（0.8167）提升，但仍未超越纯 BM25 |

## 四、核心结论
**问题1：混合检索是否优于纯向量？**
答：在 `recursive_512_0` 切分策略下，混合检索的 Recall@5（0.85）**优于纯向量（0.80）**，但 MRR（0.8250）**仅略高于纯向量（0.80）**，且未超过纯 BM25（0.85）。混合检索**并未稳赢**单路检索。

**问题2：在哪些问题上混合反而差？**
答：在“单路强命中，另一路全未命中”的问题上（如 Q5），RRF 融合会因为其它“双榜提名”的噪音文档导致正确文档排名下降。通过将 `k` 从 60 降到 10，并将向量权重从 1.0 降到 0.5，成功把 Q5 的正确文档从 rank=3 拉回 rank=2，MRR 从 0.8167 提升至 0.8250。但依然无法根治。

**问题3：为什么混合检索无法达到 0.85？**
答：因为 Q4、Q18、Q20 是**检索器完全漏召（rank=0）**。Q4 和 Q18 受限于数学字体（γ vs 𝛾）的评估器错判，Q20 受限于“不知道”与“不是明确给出”的语义鸿沟。RRF 是融合排序算法，只能对已召回的文档重新排名，无法创造新的召回。

## 五、Badcase 归因表（≥5条）

| 编号 | 问题 | 类型 | 具体原因 |
| :--- | :--- | :--- | :--- |
| **Q4** | 在MDP的五元组中，γ代表什么？ | 漏召/符号歧义 | 数学字体 `γ` 与 `𝛾` 在文本匹配时不一致，导致评估器误判为漏召（实际检索到了正确内容） |
| **Q5** | 强化学习与监督/无监督学习最直观的区别是什么？ | 误召/融合挤占 | 向量排0、BM25排1。调参后混合排第2，证明了降低k值和向量权重能缓解噪音挤占 |
| **Q18** | 在强化学习中，引入折扣因子γ（0≤γ≤1）的目的是什么？请结合金融例子说明。 | 长距离依赖 | 正确文本块中“折扣因子”、“金融例子”相距较远，且受限于 `γ` 字体不一致，未被完整匹配 |
| **Q20** | 在不知道环境动态（P和R）的情况下，有哪两种解决思路？ | 语义歧义 | 问题用词是“不知道”，但文档用词是“不是明确给出的”，语义匹配存在鸿沟 |
| **Q3** | 马尔可夫决策过程（MDP）可以由哪五元组表示？ | 漏召/评估器污染 | 初版评估因 `source_context` 包含五元组公式而漏判，修正评估器后命中，可作为“评估器污染”的典型案例记录 |

## 六、未来优化方向
1. **改进评估器**：引入更鲁棒的文本归一化（解决 γ 字体问题）。
2. **调优 RRF**：减小 `candidate_k` 或调整权重，抑制“双榜提分”带来的噪音挤占。
3. **查询扩展**：对 Q20 这种“不知道 vs 不是明确给出”的语义鸿沟，可尝试查询改写（Query Rewriting）。
