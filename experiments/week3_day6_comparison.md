# Week 3 Day 6: 分层归因与对比实验报告

## 1. 实验背景与目标
本实验旨在评估三种不同 RAG 方案（纯 LLM、基础 RAG、自适应 RAG）在强化学习/MDP 领域问答中的表现，并通过分层归因与路由轨迹分析，定位系统瓶颈，为后续优化指明方向。

## 2. 实验设置
- **测试集**：10 条高质量问答对（来源：课件与教材）。
- **评估指标**：RAGAS 三指标（Faithfulness 忠实度、Context Precision 上下文精确率、Context Recall 上下文召回率）。
- **评估模型**：DeepSeek API (`deepseek-chat`) 作为裁判 LLM。
- **总评估样本数**：30 条（3 种方案 × 10 个问题）。

## 3. 方案对比结果
| 方案 | Faithfulness | Context Precision | Context Recall |
| :--- | :--- | :--- | :--- |
| 纯 LLM | 0.0000 | 0.0000 | 0.0000 |
| 基础 RAG | 0.9000 | 0.9000 | 0.9000 |
| **自适应 RAG** | **1.0000** | 0.8656 | **1.0000** |

**结论**：
1. **纯 LLM 全面溃败**：因为没有外部知识检索，大模型依靠自身记忆无法准确回答专业问题，所有指标均为 0。
2. **自适应 RAG 优于基础 RAG**：自适应 RAG 在 **Faithfulness（1.0 vs 0.9）** 和 **Context Recall（1.0 vs 0.9）** 上均优于基础 RAG，满足“至少在 1 个指标上优于基础 RAG”的验证条件。

## 4. 分层归因分析
| 错误层级 | 错误数量 | 错误率 | 归因说明 |
| :--- | :--- | :--- | :--- |
| Query 理解 | 10 | 33.3% | 纯 LLM 方案无检索能力，导致全部 10 道题答错，归为此层。 |
| 检索 | 1 | 3.3% | 基础 RAG 中有 1 道题完全未召回正确文档，属于检索器瓶颈。 |
| 重排 | 0 | 0.0% | 所有检索到的资料均被正确排序，无重排问题。 |
| 生成 | 0 | 0.0% | 资料给对后，大模型均能忠实作答，无幻觉问题。 |

**根因定位**：
系统的核心瓶颈在于 **“检索召回率”** 而非“生成质量”。一旦检索到正确文档，系统表现极度稳定。后续优化方向应聚焦于提升检索器的召回能力。

## 5. 变式练习：自适应 RAG 路由轨迹与错误归因关联分析
| route_taken | faithfulness | context_precision | context_recall | 触发次数 |
| :--- | :--- | :--- | :--- | :--- |
| exact | 1.0000 | 0.8222 | 1.0000 | 4 |
| hybrid | 0.8889 | 0.7611 | 1.0000 | 3 |
| semantic | 1.0000 | 1.0000 | 1.0000 | 3 |

**轨迹分析结论**：
1. **所有路由的召回率均为 1.0**：说明路由分发机制极其有效，能精准地把 Query 送到对应的检索器，没有出现“找不全资料”的问题。
2. **`semantic` 路由表现最完美**：概念理解类问题（什么是X）走语义检索精度达到了 1.0。
3. **`hybrid` 路由的精度（0.76）最低**：说明混合检索（RRF 融合）在召回高的情况下，混入了噪音。这是后续优化的核心方向——**应调优 RRF 权重或引入轻量级重排（Reranker）来提升 `hybrid` 路由的上下文精度**。
4. **`exact` 路由的精度（0.82）有待提升**：BM25 关键词检索对同义词泛化不足，后续可考虑加一层 query 改写。

## 6. 最终优化建议
1. **优先优化 `hybrid` 路由的精度**：通过实验调整 RRF 的 `k` 值和向量/BM25 的权重比例，或在混合检索后加一个轻量级重排模型。
2. **扩充测试集规模**：从 10 条增至 50+ 条，降低统计偶然性，获得更稳健的结论。
3. **针对“检索”层错误进行专项分析**：虽然目前只有 1 条，但随着测试集扩大会增多，需要建立 Badcase 跟踪机制。
