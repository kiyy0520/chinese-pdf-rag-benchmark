# Week 3 最终实验报告：自适应 RAG 系统评估与优化

## 一、项目背景与目标

本项目基于中文强化学习课件构建 RAG 问答系统。第 2 周完成了基础 RAG 链路（PDF 解析 → 切分 → 向量化 → 检索 → 生成 → RAGAS 评估）。第 3 周的目标是在此基础上引入**自适应能力**，让系统根据 Query 类型动态选择检索策略，并在生成前加入引用溯源、冲突检测和自适应拒答，最终通过分层归因表量化系统瓶颈。

第 3 周的核心问题有三个：

1. **检索路径单一**：第 2 周只用了向量检索，面对术语、公式类 Query 表现不佳。能否引入多路检索并按需分发？
2. **重排成本高**：每次都跑 Reranker 延迟过高，能否只在必要时触发？
3. **无法定位瓶颈**：RAGAS 只给总分，不能告诉我们是 Query 理解、检索、重排还是生成出了问题。

## 二、系统架构

系统在第 2 周基础 RAG 之上，增加了四层增强：

1. **路由层**（`src/routing/`）：基于正则规则的 Query 分类器，将问题分为 skip / exact / semantic / hybrid 四类，分发到不同检索器。
2. **重排层**（`src/retrieval/conditional_reranker.py`）：条件触发 Reranker，仅在检索一致性低时执行。
3. **生成增强层**（`src/generation/`）：引用溯源（citation）、冲突检测（conflict_detector）、自适应拒答（refusal）。
4. **评估层**（`src/evaluation/` + `experiments/week3_*`）：RAGAS 三指标、分层归因、路由轨迹分析。

## 三、路由决策实验（Day 1-2）

### 3.1 路由分类规则

分类器基于正则实现，四类路由触发条件如下：

| 路由类型 | 触发条件 | 检索方式 |
|---|---|---|
| skip | 命中闲聊/超范围模式（"你好"、"天气"等） | 不检索，直接回复 |
| exact | 命中术语/公式/符号（"五元组"、"γ"、"公式"等） | BM25 关键词检索 |
| semantic | 命中"什么是"、"为什么"、"如何理解"等 | 向量语义检索 |
| hybrid | 命中"区别"、"步骤"、"对比"、"描述"等 | BM25 + 向量 RRF 融合 |

### 3.2 路由链路测试

在 12 条测试 Query 上验证了四条路由均可正确分发。样例：

| Query | 期望路由 | 实际路由 | 是否正确 |
|---|---|---|---|
| "你好，你是谁？" | skip | skip | ✅ |
| "MDP 的五元组是什么？" | exact | exact | ✅ |
| "什么是马尔可夫过程？" | semantic | semantic | ✅ |
| "价值迭代和策略迭代有哪些区别？" | hybrid | hybrid | ✅ |

规则分类器的优势在于**零训练、可解释、迭代快**，缺点是泛化能力弱于模型，对未见过的表达方式可能误判。

## 四、条件 Rerank 实验（Day 3）

### 4.1 实验设计

对比三种重排策略：

- **pure_vector**：纯向量检索，不重排
- **always_rerank**：始终跑 Reranker
- **conditional_rerank**：仅当检索一致性低于阈值时触发

通过 3 组阈值扫描（loose / baseline / strict）找到最佳平衡点。

### 4.2 实验结果

| 方案 | Recall@5 | MRR | 延迟（ms） | 触发比例 |
|---|---|---|---|---|
| pure_vector | 0.30 | 0.30 | 2.88 | 0% |
| always_rerank | 0.35 | 0.32 | 85.20 | 100% |
| conditional_rerank (baseline) | 0.35 | 0.32 | 12.60 | 35% |

**结论**：

1. Reranker 确实能提升 Recall@5（0.30 → 0.35），但代价是延迟飙升（2.88ms → 85.20ms）。
2. 条件 Rerank 在几乎不损失效果的前提下，把延迟压回到 12.60ms，节省了 85% 的重排成本。
3. 触发比例 35% 说明"大部分 Query 的检索结果其实不需要重排"，这验证了条件触发的合理性。

## 五、引用溯源与冲突检测（Day 4）

### 5.1 引用溯源

生成层强制要求 LLM 在回答后附带来源（source + chunk_id）。样例：

```json
{
  "answer": "MDP 可以由五元组 (S, A, P_sa, γ, R) 表示...",
  "sources": [
    {"source": "sjtju_rl_lecture.pdf", "chunk_id": 3},
    {"source": "mdp_lecture.pdf", "chunk_id": 7}
  ]
}
```

引用溯源的价值在于：用户发现答案错误时，可以直接点击 chunk_id 回溯原文，判断是"检索错了"还是"生成错了"。

### 5.2 冲突检测

当多个检索结果的语义相似度低于阈值时，说明知识库中存在矛盾信息，系统主动提示用户。

在 5 条精心构造的矛盾用例上，冲突检测的召回率为 80%（4/5）。漏检的 1 条是两个文档用不同措辞表达同一含义，语义相似度未低于阈值。

## 六、自适应拒答实验（Day 5）

### 6.1 实验设计

测试 20 条用例：5 条超范围问题（S1-S5）+ 15 条正常问题（N1-N15）。

拒答策略：检索置信度（mean_sim）低于阈值 0.45，或方差过小且均值偏低时，拒绝作答。

### 6.2 实验结果

| 用例类型 | 总数 | 正确拒答 | 正确回答 | 准确率 |
|---|---|---|---|---|
| 超范围问题（S 类） | 5 | 5 | 0 | 100% |
| 正常问题（N 类） | 15 | 0 | 15 | 100% |
| **合计** | **20** | **5** | **15** | **100%** |

**结论**：

1. **拒答准确率 100%**（5/5），远超 ≥90% 的目标。
2. **误拒率 0%**（0/15），远低于 <10% 的目标。
3. 拒答机制完全依赖检索置信度，无需额外训练，可解释性强。

样例输出：

- 输入 "今天秦皇岛天气怎么样？" → 输出 "根据现有知识库，我无法回答这个问题。"
- 输入 "员工年假有多少天？" → 输出 "年假：入职满一年的员工，每年享有 10 天带薪年假。"

## 七、分层归因分析（Day 6）

### 7.1 归因规则

按 RAGAS 分数自动归因：

- **Query 理解层**：纯 LLM 方案无检索能力，全部归为此层
- **检索层**：context_recall < 0.6，说明完全没找到正确文档
- **重排层**：context_recall ≥ 0.6 但 context_precision < 0.6，说明找对了但排序差
- **生成层**：检索指标正常但 faithfulness < 0.6，说明资料对了但大模型乱答

### 7.2 分层归因表（30 条总样本）

| 错误层级 | 错误数量 | 错误率 | 归因说明 |
|---|---|---|---|
| Query 理解 | 10 | 33.3% | 纯 LLM 方案无检索能力，全部 10 道题答错 |
| 检索 | 1 | 3.3% | 基础 RAG 有 1 道题完全未召回正确文档 |
| 重排 | 0 | 0.0% | 检索到的资料均被正确排序 |
| 生成 | 0 | 0.0% | 资料给对后，大模型均能忠实作答 |

**根因定位**：

- 33.3% 是纯 LLM 造成的（无检索能力的必然结果），不代表自适应 RAG 的实际表现。
- 真实瓶颈是 3.3% 的检索漏召。一旦检索到正确文档，重排和生成层零错误。
- **后续优化应聚焦于提升检索召回率，而非调 Prompt 或加 Reranker。**

## 八、三方案对比实验（Day 6）

### 8.1 实验设计

在同一测试集（10 个端到端问题）上，跑三种方案：

| 方案 | 检索方式 | 生成方式 |
|---|---|---|
| 纯 LLM | 无检索 | 直接问 LLM |
| 基础 RAG | 向量检索 top-3 | LLM 根据检索内容生成 |
| 自适应 RAG | 路由分发 + 条件 Rerank | LLM 根据检索内容生成 |

评估裁判 LLM：DeepSeek Chat。
RAGAS 三指标：Faithfulness / Context Precision / Context Recall。

### 8.2 对比结果

| 方案 | Faithfulness | Context Precision | Context Recall |
|---|---|---|---|
| 纯 LLM | 0.0000 | 0.0000 | 0.0000 |
| 基础 RAG | 0.9000 | 0.9000 | 0.9000 |
| **自适应 RAG** | **1.0000** | 0.8656 | **1.0000** |

**结论**：

1. **纯 LLM 全面溃败**：无检索辅助，在专业领域无法作答。
2. **自适应 RAG 在 2 个指标上优于基础 RAG**：
   - Faithfulness 从 0.9 提升到 **1.0**（+0.1）
   - Context Recall 从 0.9 提升到 **1.0**（+0.1）
3. **Context Precision 略低**（0.8656 vs 0.9）：说明混合检索引入了少量噪音，后续可通过 RRF 权重调优优化。
4. 验证条件满足：**自适应 RAG 至少在一个指标上优于基础 RAG**。

## 九、路由轨迹分析（变式练习）

### 9.1 实验设计

为自适应 RAG 增加路由轨迹记录，分析不同路由与 RAGAS 指标的关系。

### 9.2 路由轨迹表

| 路由 | Faithfulness | Context Precision | Context Recall | 触发次数 |
|---|---|---|---|---|
| exact | 1.0000 | 0.8222 | 1.0000 | 4 |
| hybrid | 0.8889 | 0.7611 | 1.0000 | 3 |
| semantic | 1.0000 | 1.0000 | 1.0000 | 3 |

**结论**：

1. **所有路由的 Context Recall 均为 1.0**：说明路由分发机制有效，没有出现漏召。
2. **`semantic` 路由精度最高（1.0）**：概念理解类问题走向量检索是最佳选择。
3. **`hybrid` 路由精度最低（0.7611）**：RRF 融合混入了噪音，这是后续优化重点。
4. **`exact` 路由精度中等（0.8222）**：BM25 对同义词泛化不足，可考虑加 query 改写。

### 9.3 优化建议

| 优化方向 | 具体措施 | 预期收益 |
|---|---|---|
| 提升 hybrid 精度 | 调整 RRF 的 k 值和权重，或在融合后加轻量级 Reranker | Precision 从 0.76 提升到 0.85+ |
| 提升 exact 精度 | 加 query 改写，扩展同义词 | Precision 从 0.82 提升到 0.90+ |
| 提升整体召回 | 扩大候选集（top_k 从 5 提到 10） | 检索层错误率从 3.3% 降到 1% 以下 |

## 十、结论与改进方向

### 10.1 核心结论

1. **自适应 RAG 优于基础 RAG**：在 Faithfulness 和 Context Recall 上均提升 0.1。
2. **条件 Rerank 有效**：延迟从 85.2ms 降到 12.6ms，节省 85% 成本。
3. **拒答准确率 100%**：超范围问题全部正确拒绝，正常问题零误拒。
4. **系统瓶颈在检索层**：分层归因表显示检索错误率 3.3%，其余三层均零错误。
5. **路由分发机制有效**：所有路由的 Recall 均为 1.0，说明分发策略没有让任何一个 Query 走错路。

### 10.2 后续优化方向

| 优先级 | 优化项 | 预期收益 |
|---|---|---|
| P0 | 优化 hybrid 路由的 RRF 权重 | Context Precision 提升 0.1 |
| P0 | 扩大候选集 top_k | 检索错误率降到 1% 以下 |
| P1 | 引入 query 改写 | exact 路由精度提升 |
| P1 | 扩充测试集到 50+ 条 | 结论统计更稳健 |
| P2 | 支持多轮对话 | 系统能力扩展 |
