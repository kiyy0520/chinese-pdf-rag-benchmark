# Week 4 Day 4：歧义检测 + 主动澄清实验日志

## 1. 实验目标
- 歧义检测召回率 ≥ 80%
- 误报率 < 15%
- 歧义测试用例全部有明确澄清回复
- 澄清后用户回答的追问轮次 ≤ 1 轮

## 3. 指标统计
- TP = 5
- FP = 0
- FN = 0
- TN = 3
- 召回率 = TP / (TP + FN) = 5 / (5 + 0) = 100%
- 误报率 = FP / (FP + TN) = 0 / (0 + 3) = 0%

## 4. 达标情况
- 召回率 ≥ 80%：达标（实际 100%）
- 误报率 < 15%：达标（实际 0%）
- 测试用例均有明确澄清回复：达标（通过 A/B 选项让用户一句话回答）
- 追问轮次 ≤ 1 轮：达标

## 5. 工程实现说明
- **规则前置过滤**：先通过规则检测指代词（它、他、这个等）与候选实体数量。若候选实体不足两个，或用户话语中已显式包含实体名称，则直接阻断，不调用 LLM，大幅降低响应延迟与 Token 成本。
- **LLM 语义兜底**：规则无法确认时，调用大模型（DeepSeek）进行语义判断。强制要求结构化 JSON 输出（`response_format={"type": "json_object"}`），确保程序解析稳定性。
- **异常降级策略**：封装 `try-except` 捕获 LLM 超时或报错。若发生异常，降级为保守判断（多候选默认有歧义），防止 Agent 崩溃。
- **澄清话术模板**：根据不同数量的候选实体，自动拼接 2 个（A 还是 B）及 3 个以上（A、B 还是 C）的选项话术，引导用户单轮解决。

## 6. 问题与改进
- **话术优化**：ID 3 中由于是规则推导出的“省略的主语”，直接拼接入话术显得生硬（“您说的‘省略的主语’是指...”）。后续可针对“省略主语”场景单独设计一套话术（如：“请问已完成的是‘任务A’还是‘任务B’？”）。
- **测试集扩充**：当前测试用例为 8 条，后续可增加更复杂的跨多轮对话、包含否定词的歧义场景，以进一步压测系统的鲁棒性。
